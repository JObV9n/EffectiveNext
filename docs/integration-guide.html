Integration Guide

Add effectiveNext to any Next.js project — new, existing, or legacy.

Overview

effectiveNext wraps next build and next dev with a preprocessing layer that scans files, builds a dependency graph, caches parser output, and tracks changes. You don't modify your source code — effectiveNext sits in front of Next.js.

ⓘ Zero source changes required
effectiveNext reads your existing next.config.js, tsconfig.json, and package.json. No configuration changes needed to start.
Install time
< 30s
Single binary, no deps

New Project

Setting up effectiveNext in a fresh Next.js project.

1

Create your Next.js app

npx create-next-app@latest my-app
cd my-app
2

Install effectiveNext

# From source
git clone https://github.com/effective-next-dev/effective-next.git /tmp/effective-next
cd /tmp/effective-next && go build -o /usr/local/bin/effective-next ./cmd/effective-next

# Or via go install
go install github.com/effective-next-dev/effective-next/cmd/effective-next@latest
3

Verify environment

cd ~/my-app
effective-next doctor

Expected output:

effective-next: Environment Check
  [PASS] Go version: 1.24+
  [PASS] Node.js: v20.x.x
  [PASS] Package manager: npm
  [PASS] Next.js: 14.x.x
  [PASS] next.config.js found
  [PASS] Project directory: /home/user/my-app
4

Build

effective-next build

effectiveNext preprocesses your project, then invokes next build.

5

Start dev server

effective-next dev

Replaces next dev with faster incremental rebuilds.

✓ Done
Your project now uses effectiveNext. Add effective-next build to your deployment scripts.

Existing Project

Migrating an active Next.js project to effectiveNext.

Step 1: Check Compatibility

effective-next doctor

Ensure all checks pass. Common issues:

CheckFix
Node.js not foundInstall Node.js 18+
Next.js not foundRun npm install
next.config missingCreate next.config.js

2: Analyze Your Project

effective-next analyze

This shows file counts, dependency graph stats, routes, and circular dependencies — without modifying anything.

3: Dry Run

effective-next build --dry-run

Preview the preprocessing pipeline without invoking next build.

4: First Build

effective-next build

The first build is a cold build. Subsequent builds are faster due to caching.

5: Update Scripts

Replace next build in your package.json:

{
  "scripts": {
    "build": "effective-next build",
    "dev": "effective-next dev",
    "start": "next start"
  }
}
ⓘ No breaking changes
effectiveNext invokes next build internally. Your existing CI/CD, deployment, and next start commands continue to work.

Webpack Projects

effectiveNext does not replace Webpack. It preprocesses files before Next.js runs Webpack. Custom Webpack configs in next.config.js continue to work.

// next.config.js — works with effectiveNext
module.exports = {
  webpack: (config) => {
    config.resolve.alias['@'] = './src'
    return config
  },
  experimental: {
    appDir: true
  }
}

Pages Router Only

If your project uses only pages/ (no app/ directory), effectiveNext detects this automatically:

effective-next analyze
# Routes:         24
# App Router:     false
# Pages Router:   true

Migrating from CRA / Vite / Other

If you're migrating to Next.js and want to use effectiveNext:

  1. Complete your Next.js migration first
  2. Verify next build works standalone
  3. Then add effectiveNext in front
⚠ effectiveNext does not replace Next.js
effectiveNext is a preprocessing accelerator. You still need a working Next.js project.

Full Config Example

# effective-next.yaml

# Number of worker goroutines (auto = all CPU cores)
workers: auto

cache:
  # Enable/disable binary caching
  enabled: true
  # Compression algorithm: zstd, gzip, none
  compression: zstd
  # Maximum cache size in MB (0 = unlimited)
  maxSizeMB: 25600
  # Cache directory (relative to project root)
  dir: .effective-next/cache

scanner:
  # Directories to skip during scanning
  ignore:
    - node_modules
    - .next
    - .git
    - dist
    - coverage
    - out
    - .vercel
    - .effective-next

watch:
  # Enable file watching in dev mode
  enabled: true
  # Debounce interval in milliseconds
  debounceMs: 100

optimization:
  # Enable asset optimization (hashing, dedup)
  assets: true
  # Enable CSS dependency tracking
  css: true

# Preset: default, ci, low-memory, desktop
profile: default

Profiles

Presets for different environments.

default
Balanced settings for most machines. Auto-detects CPU count.
ci
Fixed worker count, caching enabled, no watch. Predictable for CI/CD.
low-memory
Reduced workers (2 or NumCPU/2), 5 GB cache limit. For constrained environments.
desktop
Maximum parallelism. Uses all CPU cores. Best for developer machines.

Monorepo Support

effectiveNext works in monorepo setups (Turborepo, pnpm workspaces, Nx).

Per-Package Setup

Run effectiveNext from each Next.js package root:

# Turborepo structure
packages/
  web/              # Next.js app
    effective-next.yaml
    next.config.js
    app/
  ui/               # Shared library (not Next.js)
  docs/             # Another Next.js app
    effective-next.yaml
    next.config.js
    app/
# In each Next.js package
cd packages/web
effective-next build

cd packages/docs
effective-next build

Turborepo Integration

{
  "scripts": {
    "build": "turbo run build"
  },
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": [".next/**", "!.next/cache/**", ".effective-next/**"]
    }
  }
}

Shared Cache

Point all packages to a shared cache directory:

# packages/web/effective-next.yaml
cache:
  dir: ../../.effective-next-cache

# packages/docs/effective-next.yaml
cache:
  dir: ../../.effective-next-cache
ⓘ Separate build databases
Each package gets its own .effective-next/build.db since dependency graphs differ per package.

Custom Cache Location

Store the cache on a fast disk or shared volume:

# effective-next.yaml
cache:
  dir: /mnt/ssd/effective-next-cache
  maxSizeMB: 51200  # 50 GB on fast SSD

Cache in Git (optional)

Some teams commit the cache for faster CI:

# .gitignore
.effective-next/build.db
.effective-next/cache/*.zst
# Keep manifest.json for CI speedup

CI/CD Integration

GitHub Actions

# .github/workflows/build.yml
name: Build
on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

          node-version: '20'

      - run: npm ci

      - name: Install effectiveNext
        run: go install ./cmd/effective-next

      - name: Build
        run: effective-next build --workers 4

Vercel

Cache in CI

Cache the .effective-next/ directory between CI runs:

# GitHub Actions cache
- uses: actions/cache@v4
  with:
    path: .effective-next
    key: effective-next-${{ hashFiles('**/*.ts', '**/*.tsx') }}
    restore-keys: effective-next-
✓ CI builds are faster
With .effective-next/ cached, incremental CI builds skip scanning and parsing unchanged files.

Docker

Multi-Stage Build

# Build stage
FROM golang:1.24 AS effective-next
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /effective-next ./cmd/effective-next

# Application stage
FROM node:20-slim
WORKDIR /app
COPY --from=effective-next /effective-next /usr/local/bin/
COPY package*.json ./
RUN npm ci
COPY . .
RUN effective-next build --workers 4
EXPOSE 3000
CMD ["next", "start"]

With Cache Mount

RUN --mount=type=cache,target=/app/.effective-next effective-next build

Troubleshooting

ProblemSolution
effective-next: command not found Add Go bin to PATH: export PATH=$PATH:$(go env GOPATH)/bin
next binary not found Run npm install in project root
failed to open build database Run effective-next clean --all to reset
sqlite3: unknown driver Enable CGO: export CGO_ENABLED=1
Build slower than expected Run effective-next doctor, check effective-next cache stats
Watch not detecting changes Check inotify limits: cat /proc/sys/fs/inotify/max_user_watches

Port already in use Use effective-next dev -p 3001
TypeScript errors during build Run tsc --noEmit first to check types
Monorepo: graph is incomplete Run effectiveNext from each Next.js package root separately

FAQ

Does effectiveNext replace Next.js?

No. effectiveNext preprocesses files and invokes next build / next dev internally. Your app is still built by Next.js.

Do I need to change my source code?

No. effectiveNext reads your existing files. No imports, routes, or configuration changes required.

Will my Vercel / Netlify deployment still work?

Yes. Set your build command to effective-next build in your deployment config. effectiveNext invokes next build which produces standard output.

What if SWC is not installed?

effectiveNext falls back to a regex-based parser automatically. Install @swc/cli for faster parsing.

Does it work with React Server Components?

Yes. effectiveNext detects 'use client' and 'use server' directives. It tracks Server Components, Client Components, and Server Actions.

How much disk does the cache use?

Typically 50-200 MB for medium projects. Set cache.maxSizeMB to limit growth.

Can I use it with Turborepo?

Yes. Run effectiveNext in each Next.js package. Cache the .effective-next/ directory between runs.

Does it support Yarn / pnpm?

Yes. effectiveNext detects the package manager automatically via effective-next doctor.

What happens on the first build?

First builds are cold — everything is scanned and parsed from scratch. Subsequent builds reuse the cache for faster incremental updates.

Is it safe for production?

Yes. effectiveNext does not modify source files. It only writes to .effective-next/ (cache and database). Running effective-next clean --all removes all effectiveNext state.
