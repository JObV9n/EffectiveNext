Developer Guide

Building, testing, and contributing to effectiveNext.

Repository Layout

cmd/effective-next/ Application entrypoint pkg/ cli/ CLI commands (Cobra) config/ Configuration loading and validation scanner/ Concurrent filesystem scanner graph/ Dependency graph + SQLite persistence parser/ SWC parser + regex fallback + LRU cache cache/ Binary cache (Zstd + SQLite) db/ SQLite build database (10 tables) routes/ Next.js route detection css/ CSS dependency tracking assets/ Asset optimization (hash, dedup) scheduler/ DAG + priority work-stealing scheduler watch/ fsnotify file watcher manifest/ Manifest generation engine/ Incremental build engine observability/ Metrics, tracing, profiling plugins/ Plugin lifecycle system fs/ Cross-platform filesystem abstraction hash/ xxHash64 content hashing internal/testutil/ Test helpers test/ Integration tests and fixtures

Build

# Standard build
go build -o bin/effective-next ./cmd/effective-next

# Optimized release build
go build -ldflags="-s -w" -o bin/effective-next ./cmd/effective-next

# Build with race detector
go build -race -o bin/effective-next ./cmd/effective-next

# Make targets
make build    # Build binary
make all      # Format, vet, test, build

# Verbose output
go test ./... -v

# Run specific package
go test ./pkg/scanner/ -v

# Run with race detector

go test ./pkg/parser/ -run TestParseContent_StaticImports -v

pkg/graph — Dependency Graph

Concurrent in-memory dependency graph with SQLite persistence.

Key Types

type Node struct {
    ID       string
    Path     string
    Type     NodeType   // js, ts, tsx, jsx, css, json, image, route
    Hash     uint64
    Size     int64
    Metadata map[string]string
}

type Edge struct {
    Source  string
    Target  string
    Type    EdgeType    // static-import, dynamic-import, css-import
    Dynamic bool
}

SQLite Persistence

store, _ := graph.OpenStore("graph.db")
store.Save(graph)        // persist in-memory graph
graph, _ := store.Load()  // restore from SQLite
store.Clear()            // wipe persisted data

pkg/parser — Parser with LRU Cache

Extracts imports, exports, and metadata from source files with bounded caching.

// Basic parsing
result, err := parser.ParseFile("src/app.tsx")

// Cached parsing
cache := parser.NewParseCache(10000)

if cached := cache.Get(path); cached != nil {
    return cached, nil
}

result, _ := parser.ParseFile(path)
cache.Put(path, result, hash)

// Invalidate changed files
removed := cache.Invalidate(currentHashes)

pkg/scheduler — Priority Scheduler

Work-stealing scheduler with heap-based priority queue for dependency-ordered execution.

ps := scheduler.NewPriorityScheduler(8)

ps.AddTask(&scheduler.Task{
    ID:       "scan",
    Priority: 10,
    Fn:       func() error { return scan() },
})

ps.AddTask(&scheduler.Task{
    ID:       "parse",
    Priority: 5,
    Deps:     []string{"scan"},
    Fn:       func() error { return parse() },
})

ps.Run()

pkg/observability — Tracing & Profiling

// Trace spans
tracer := observability.NewTracer()
span := tracer.StartSpan("build", nil)
// ... do work
tracer.FinishSpan(span)

// Worker utilization
wu := observability.NewWorkerUtilization(8)
wu.RecordSample(4)  // 4 of 8 workers busy
avg := wu.AverageUtilization()

// Runtime profiling
profile := observability.CaptureProfile()

// Memory tracking
mt := observability.NewMemoryTracker()
mt.Snapshot()
peak := mt.Peak()

pkg/db — Build Database

SQLite-backed storage with 10 tables for files, hashes, dependencies, routes, assets, cache, stats, benchmarks, and history.

database, _ := db.Open(".effective-next/build.db")
defer database.Close()

// Build lifecycle
buildID, _ := database.StartBuild()
database.RecordStat(buildID, "files_scanned", 1247)
database.FinishBuild(buildID, "success", metrics)

// Cache operations
database.UpsertCacheEntry(db.CacheEntry{...})
entry, _ := database.GetCacheEntry("key")

// Build history
history, _ := database.GetBuildHistory(10)

Architecture Decisions

Decision Rationale
SQLite Single-file DB, WAL mode for concurrent reads, zero-config, battle-tested
xxHash64 Fastest non-crypto hash (~13 GB/s), zero allocations for in-memory data
Zstd Better ratio than gzip, faster compression/decompression, configurable levels
LRU Cache Bounded memory, O(1) operations, automatic eviction, hash-based invalidation
Work-stealing Higher throughput than simple goroutine pools, priority-aware scheduling
